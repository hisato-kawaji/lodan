# Memory — 修正パターン・好みの記録

## コード編集の修正パターン

- **doc コメントつきアイテムの直前に新アイテムを挿入しない**（pr-review #47・#49・#92・#104・#120・#124 で計 6 回指摘）。
  目視では防げていないので、挿入したら `grep -n "<新しいアイテム>" -B8 <file>` で機械的に確かめる。
  既存 fn の `///` doc と fn 本体の間に挿入すると、doc が新アイテムに誤アタッチされ元の fn が doc なしになる。
  fn だけでなく `impl` ブロック（#120）や `#[derive]` 付き struct（#124: `pub struct X {` を anchor にすると derive と doc の間に入る）でも起きる。
  挿入位置は「既存の doc コメントの開始行より前」か「既存アイテムの閉じブレースの後」にする。パッチスクリプトの最後に確認の grep を組み込む。
- **commit / push / PR コメントはテスト通過をシェルで機械的にゲートする**（#124 で 2 回連続、コンパイルできない head を push）。
  `cargo test | grep | awk` は失敗しても exit 0 なので `&&` はゲートにならない。`out=$(…); case "$out" in *"failed=0"*) git push ;; esac` の形にする。
  テストモジュールに fn を足すときは、そのモジュールの `use` が `super::*` か個別 import かを先に見る。
- **ブランチ削除は `gh pr view --json state` が `MERGED` のときだけ**（#129: 並行してマージした #130 のせいで衝突状態になり `gh pr merge` が失敗したのに、`;` で繋いだ後続がブランチを消して PR が close された。`refs/pull/<n>/head` から復元できる）。
- **rebase の衝突解消でテストの閉じ括弧が消える**（#124: HEAD 側の hunk が最後のテストの `}` を含まないのに head+mine を連結した）。
  解消したら `rebase --continue` の前に `cargo check --all-targets` を通す。

## 検証の作法

- PR 本文に「手動確認済み」と書く前に必ず実際に検証する。シグナル経路など
  ユニットテスト困難なものは実バイナリ＋モックサーバの E2E で確認し、
  検証した範囲だけを正確に記載する（#49 で実施した方式:
  ハングするモックサーバ + SIGINT 送出 + transcript 確認）。
- ライブラリ挙動の主張（例: tokio `output()` の kill_on_drop）は
  `~/.cargo/registry` のソースで裏取りしてから書く。

## レビュー運用

- pr-reviewer の WARN は非ブロッキングでも原則対応してからマージする
  （記述を直すより実装を直して記述を真にする方向を優先。例: #49 の kill_on_drop(true) 明示設定）。

## 2026-09 のセッションで決まった作法（詳細は `.claude/scratch/mega-prompt-2026-09-21.md`）

- **権限・サンドボックス・予算に関わる PR は「実行して壊してみて」と依頼する**。毎回実在の穴が出た
  （#98/#99/#102/#103/#104/#106/#107 で各 2〜4 周）。依頼文を書く過程で自分でも穴に気づくことが多い。
- **レビュー依頼文の安全条項は必須**（2026-09-21 に、レビュアーが cwd を取り違えて `.env` の鍵で
  Moonshot の実 API を 1 回叩いた）: `git archive <sha>` の pristine export だけを使う /
  lodan は `cd <scratch> || exit 1` の後 `env -i HOME=… PATH=… LODAN_PROVIDER=local LODAN_BASE_URL=<mock>` で起動 /
  `--provider kimi|sakura|sakana` を渡さない / このリポジトリの作業ツリーに触らない。
- レビュー中の worktree は編集しない（直したくなったらローカルコミットに留め、verdict の後で push）。
- 修正を外しても通るテストを書かない。変異試験は同じディレクトリでその場で書き換え、戻したら `touch`。
- 「起動できない環境では skip」するテストは、skip したことを必ず表示させる。Linux の確認は Docker でできる。
- `user` メッセージを 2 つ続けて履歴に積まない（役割の交互を要求するチャットテンプレートがある）。
- 記述と実装が食い違ったら、原則は実装を直す。ただし既存の一貫した挙動（例: 設定テーブルのキー単位の重ね合わせ）と
  食い違っていたのが記述の側なら、記述を直す。

## 採用した設計と理由

- LLM 使用量の計上は**クライアントを包む層**（`llm::metered`）。呼び出し元ごとに足すと次の呼び出し元で漏れる。
  呼び出しの種別やプランモードのように「クライアントが知らない文脈」は tokio の task-local で渡す
  （`LlmClient` のシグネチャを変えると 20 近いモックに波及するため）。
- 予算は「次のリクエストを送らない」で打ち切る（必ず LLM 呼び出しの直前で止まり、履歴が API-valid のまま残る）。
  再試行・fallback で送り直した分も 1 件ずつ数える。
- hook の `allow` は承認プロンプトを省くだけ。deny / ask ルールと `dont-ask` には勝てない（hook はプロジェクト設定からも足せる）。
  PreToolUse / PermissionRequest の「読めない判断」はブロックに倒す。
- サンドボックスは fail closed。保護は「名前の付け替え」まで考える（`.git` ごと差し替えられた）。
- `lodan config` は既定で秘密を伏せる（表示用の写しだけを加工する）。
- **メモリとして読むファイル名と trust の候補は 1 つの定数から導く**（#125: `AGENTS.md` を片方にだけ足して、そのファイルだけのリポジトリが尋ねられずに信頼された）。
  モデルへの指示を差し込める新しい置き場所（`.lodan/rules`・`.lodan/agents` …）を作ったら、必ず `trust::project_files` の候補にも足す。
- ツールの遅延ロード（`ToolSearch`）は registry 外の擬似ツール。読み込みは承認ゲートを通さないが、読み込んだ後の呼び出しは通常経路。
  `readonly` が隠す破壊的ツールは遅延にもしない（プロファイルは「見せる範囲」、権限の境界は承認ゲート）。
- 空応答（本文もツール呼び出しも無し）は 1 回だけ「答えを書け」と促す。履歴には `content: ""` で積む
  （`content` 無しの assistant を送り返すと Ollama が 400。促し経路以外の送り返しも同じ）。
- tool_result に足す文脈（path-scoped ルール）は閉じタグつきで囲み、本文中の閉じタグを潰す（hook の文脈と同じ流儀）。
- `/model` の引数はまず全体を provider として読む（ollama の `name:tag` を provider:model と誤読しない）。

- 書き込み可のサブエージェント（#134）: 子は親の承認ゲートを共有し、プロンプトは出自つきの **yes / no のみ**（`(p)` 永続化や dont-ask を子から作らせない）。
  `Task` 自身は `is_destructive() = false` のままなので、plan モードの read-only ガードは子の `admit` で別途効かせる。
  子のツール呼び出しも親と同じ hook を通し、payload の共通フィールドは親の `fire_hook` と揃える（`hook_payload` を 1 か所に。レビューで 2 回指摘された）。
  書き込み可の定義が 1 つでもあれば `Task` を非並列にする（並列 prefetch は `decide_quietly == Allow` の前提で動くため）。

- lodan がターンの途中に注入する user メッセージ（ナッジ・stop hook の理由・予算の注意書き）は `[lodan] ` で始める（#136）。
  利用者のターンと区別する印で、圧縮の境界（`compact_boundary`）はこれを数えない。数えると境界が未保存の末尾に入り、transcript のレコーダの前提が崩れた。
- transcript は append-only で原文を残し、要約は書かない（#136）。圧縮で history が縮んだ分は `Session::compacted_away` の累計で Recorder が `persisted` を縮めて追従する。
- worktree の中で走る子（`isolation: worktree`、#137）は **worktree の外のファイルに触れない**（`permission_rules::escapes_root`）。
  worktree はリポジトリの中にあるので `..` で親に戻れ、ルールの照合基準を子の cwd にするだけでは足りない（レビューで `deny = ["Read(**)"]` でも `.env` が漏れた）。
  承認ゲートのルール照合は子の cwd 基準（`decide_for_subagent(.., cwd)` / `assess_in` / `decide_quietly_in`）。
- バックグラウンドの子（`run_in_background`）は尋ねられない: `decide_quietly_in` で尋ねずに決まる呼び出しだけ通し、承認が要るものは「前景で走らせて」と拒否する。`-p` では前景で走る。
- Python heredoc で Rust の文字列を書くとき、行継続の `\` は `\\` にしない（`\\` + 改行は「エスケープされたバックスラッシュ」で、文字列に `\` と空白が残る。#137 で 9 箇所やった）。

## 却下した案と理由（2026-09-26 追加）

- #77 PR A で書き込み可のサブエージェント: `Task` は 1 ツールで `is_destructive() = false` なので、書き込み可の種類を混ぜるとプランモードの read-only ガードを素通りする。
  ゲートとモードを子に通す設計が要るので別 PR（→ #134 で実装）。
- 子の承認プロンプトに `(p)` / dont-ask を出す案: 子が出した要求で親セッションの永続ルールが増えるのは出自が分かりにくい。yes / no だけに限定。
- `--tools` 明示リスト + `tool_search` で破壊的ツールを遅延にしない案: 明示リストは `core` と同じ「見せる範囲」の指定なので、`readonly` だけを例外にして README で限定した。

## 却下した案と理由

- `reasoning_effort` を enum にする: 語彙がサーバとモデルごとに違う（Ollama は `none`、Moonshot は `low` を受ける）。素通しにした。
- Ollama 専用の `think` パラメータ: OpenAI 互換エンドポイントは `reasoning_effort = "none"` で同じことができる。それ以外は `extra_body`。
- `/goal pause` コマンド: 実行中は REPL が占有されていて入力できない。一時停止は Ctrl-C。
- goal を `meta.json` に入れる: 毎ターン書き直す対象にすると壊したときの影響が大きい。別ファイル `goal.json` に。
- 単価の内蔵: すぐ古くなる。`[pricing."<model>"]` に利用者が書いたものだけ使う。

## 2026-10-12: #65 Phase 1-3 のレビューで繰り返し出た型

- **権限の境界を「モデルに見せないこと」で作らない**。`Task` の `subagent_type` の enum は助言でしかなく、モデルは種類を名指しできる（`resume` 経由でも届く）。#154 では書き込める `plan-step` を隠して「呼べない」と書いたが 3 経路で到達された → **到達しても権限が増えない**形（子のツールを親に見えている範囲と同じに絞る）に変えた。同型: #152 で追記の成功に `mark_read` を立てて Read 必須ガードを外していた
- **「状態を確認済みにする」処理は、全体を把握しているときだけ**立てる
- **単体テストが正しくても配線は別に壊れる**。`plan_step_tools` は正しいのに `Task` への登録を `default_registry()` に差し替えても全テストが通った（レビュアーが mutation で実証）。施策には**本物の依存を 1 本通すテスト**を付け、レビュー依頼に「mutation で検出力を確かめて」と書く
- **実測レポートは「断言の根拠」を自分で崩しておく**。「全体の予算が抑える」と書いたが `max_requests` / `max_total_tokens` は既定 `None` = 無制限で成り立たなかった。ablation は**ラウンドをまたいで比較しない**（基準自体が round 間で 3-4 倍ドリフトした）
