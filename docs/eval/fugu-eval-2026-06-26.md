# lodan × fugu 能力検証 (2026-06-26)

`lodan`（release ビルド・built-in 12 ツール）を Sakana AI **fugu** プロバイダで動かし、
「仕様を明示した小〜中規模アプリ開発タスク」をどこまで自走で完遂できるかを測った記録。

## 結論

**10 / 10 タスク PASS。** すべて「仕様準拠コマンドが通るか」で機械判定し、難しめのものは
生成コードを手で確認しても本物の正答だった（eval 不使用の式パーサ、float 除算、unittest OK、
終了コード 0/1 まで正しい）。

## 手法

- バイナリ: `cargo build --release`（Read/Write/Edit/Bash/Grep/Glob/TodoWrite/MultiEdit/
  NotebookEdit/WebFetch/WebSearch/AskUserQuestion の 12 ツール）
- 実行: `lodan --provider sakana --model fugu --yes`、`SAKANA_API_KEY` はプロセス env 経由
  （`.env` を repo 外の作業 cwd に置かないため）
- プロンプト: **インターフェース仕様を明示した単一行**（REPL は行単位入力なので改行で分割
  されないよう 1 行）。先頭に軽い ReAct ナッジ
  （"state a one-line plan, then implement using the file tools, you MAY run Bash to verify"）
- 各タスクは独立ディレクトリで実行。必要なフィクスチャのみ事前配置
- 判定: タスクごとに**仕様準拠コマンド**を実行し exit 0 を PASS とする。各タスク上限 240s

| # | タスク | 結果 | 使用ツール | LoC | 仕様の要点 |
|---|---|---|---|---|---|
| 1 | todo_cli | PASS | Glob→Write→Bash | 43 | `add <text>`/`list` で todos.json に永続 |
| 2 | expr_eval | PASS | Glob→Write→Bash | 114 | 四則+括弧、**eval/exec 禁止**、`2+3*4=14` |
| 3 | wordfreq | PASS | Glob→Write | 13 | words.txt の最頻語を出力 |
| 4 | caesar | PASS | Write→Bash | 36 | encrypt/decrypt 往復 |
| 5 | fizzbuzz | PASS | Write | 9 | 1..100、3/5/15 で Fizz/Buzz/FizzBuzz |
| 6 | csv_stats | PASS | Glob→Write | 13 | data.csv の value 列平均 |
| 7 | temp_unittest | PASS | Write×2→Bash×2 | 23 | lib + unittest（**複数ファイル**）、`OK` |
| 8 | stack_ds | PASS | Write | 22 | push/pop/peek/is_empty/`__len__` |
| 9 | md2html | PASS | Glob→Write→Bash | 23 | `# ` → `<h1>`、`**x**` → `<strong>` |
| 10 | json_validator | PASS | Glob→Write→Bash | 37 | name:str / port:int(1..65535)、**終了コード 0/1** |

合計 LoC 9〜114。多くは `Glob`(探索)→`Write`(実装) を一発、一部は `Bash` で自己検証。

## スポットチェック（機械判定の裏取り）

- **expr_eval**: ソースに `eval(`/`exec(` 無し。`2+3*4=14`、`(2+3)*4=20`、`10/4=2.5`（float 除算）も正しい
- **md2html**: `# Hello` → `<h1>Hello</h1>`、`**bold**` → `<strong>bold</strong>`
- **json_validator**: good.json → `valid`/rc 0、bad.json → `invalid`/rc 1
- **temp_unittest**: `python3 -m unittest` が `OK`（lib + test の 2 ファイル生成）

## 所見

- lodan の system prompt + ツール駆動ループは、fugu でこの難易度帯（仕様明示・小〜中規模の
  単一アプリ）を**一通り完遂**できる。
- ツール選択も妥当: 探索に Glob、実装に Write、必要時に Bash で自己検証。複数ファイル生成も可。
- read-before-edit など lodan 側の規律も実機で機能（別途の編集タスクで Read→Edit を確認）。

## 未検証 / 次の候補

- 大規模マルチモジュール、長い依存解決、曖昧仕様、サーバ起動を伴うタスク
- 低ビット量子化ローカルモデル（例: Qwen2.5-Coder Q4）との比較
- 失敗時のリトライ／自己修復（今回は多くが一発成功で、修復経路は十分にテストされていない）

## 再現

```bash
# 1) release ビルド（12 ツール）
cargo build --release

# 2) .env に SAKANA_API_KEY を用意（または環境変数で export）
# 3) ハーネスを実行（仕様プロンプト + 検証コマンドを内包）
LODAN=./target/release/lodan EVAL_ROOT=$(mktemp -d) \
  bash docs/eval/fugu_eval_harness.sh
```

ハーネス `docs/eval/fugu_eval_harness.sh` に 10 タスクのプロンプトと検証コマンドを同梱。
生成物・トランスクリプトは `$EVAL_ROOT/<task>/` に残る。
